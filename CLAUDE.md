# dnd-shared — рабочие заметки

Устройство пакета и состав каталогов — в [README.md](README.md). Здесь то,
что нужно знать, прежде чем что-то здесь менять.

## Одна копия zod — несущий инвариант

`zod` объявлен **пировой** зависимостью намеренно. Если у пакета окажется
своя копия, `instanceof ZodError` в потребителе перестанет срабатывать —
проверка в `dnd-api/src/middleware/error.middleware.ts:13` промахнётся, и
ошибка проверки формы превратится из ответа 400 в ответ 500. Сломается это
молча: типы сойдутся, тесты схем пройдут, а на бою отвалится валидация.

Отсюда следствие, которое стоит помнить: **раскладывать пакет симлинком
или `npm link` нельзя.** Node резолвит модуль от его настоящего пути, и
файл из `dnd-shared/dist` найдёт `dnd-shared/node_modules/zod` — вторую
копию. Проверяется одной командой:

```bash
node -e "console.log(require.resolve('zod',{paths:['$PWD/dist']}))"
# dnd-shared/node_modules/zod  ← вторая копия, так жить нельзя
```

Установленная тегом копия своего `node_modules` не имеет и берёт zod у
потребителя — потому и работает. Тот же порядок сохраняет
`../scripts/sync-shared.sh`: он копирует собранный `dist`, а не связывает
каталоги, поэтому zod по-прежнему резолвится у потребителя.

## Правка контракта

1. Поправить `src/`, добавить тест схемы, `npm test`.
2. `../scripts/sync-shared.sh` — разложить сборку обоим потребителям.
3. Довести правку в `dnd-api` и `dnd-frontend`, прогнать их тесты.
4. Только перед выкаткой: поднять версию, тег, push, обновить ссылку
   `@dnd/shared` в обоих `package.json` (`chore(deps): @dnd/shared vX.Y.Z — ...`).

Пункты 1–3 тег не требуют. Раньше требовали — отсюда 12 тегов за две
недели.

## Что сюда не кладут

Ни Prisma, ни Express, ни React: пакет собирается и в Node, и в браузере.
Если типу нужен любой из них — его место в потребителе, а не здесь.

## Проверки

```bash
npm run lint      # biome: формат, линтер, порядок импортов
npm test          # vitest
npm run build     # tsc → dist
```

`prepare` зовёт `build` — при установке из тега пакет собирается сам.
